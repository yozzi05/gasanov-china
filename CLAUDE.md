# Правила работы с проектом G17

@AGENTS.md

Сайт Заура Гасанова (G17). **Дизайн утверждён и заморожен** - эталон зафиксирован тегом `v1.0`.
Полное описание дизайн-системы - в [DESIGN.md](DESIGN.md). Перед любой правкой прочитай его.

## 1. Что менять нельзя

Без прямого письменного разрешения владельца проекта нельзя менять:

- **Палитру** - токены `--color-*` в `src/app/globals.css` и любые цвета, записанные прямо в компонентах и SVG.
- **Шрифты** - Sofia Sans Extra Condensed и Golos Text, их начертания и размеры (`font-size`, `clamp(...)`).
- **Сетку** - брейкпоинты (380, 768, 1024 px), колонки, порядок и состав блоков на странице.
- **Отступы** - `--gutter`, `--header-h`, `--bar-h`, внутренние и внешние отступы секций и карточек.
- **Анимации** - длительности, кривые, задержки, порядок появления, поведение по скроллу и наведению,
  загрузочный экран. Список всех анимаций - в DESIGN.md.

Если задача не решается без изменения чего-то из этого списка - остановись и спроси. Не «чуть-чуть поправь»,
а именно спроси: что нужно, почему без этого никак, какие есть варианты в рамках системы.

## 2. Как добавлять новое

- Новые элементы собирай **только из существующих компонентов** (`src/components`) и **существующих токенов**.
- Нужна кнопка - `InkButton` с одним из готовых вариантов. Нужен заголовок раздела - `HanziTitle`.
  Нужна картинка - `Pic`. Нужен переход между цветными блоками - `InkEdge`. Появление по скроллу - атрибут `data-reveal`.
- Не добавляй новые цвета, шрифты, размеры текста, радиусы, тени и кривые анимаций. Бери ближайшее из того, что есть.
- Не подключай новые библиотеки без разрешения.
- Тексты, контакты, тарифы, ссылки и список кейсов правятся в `src/content/site.ts` - это контент, а не дизайн.
  Места с пометкой «УТОЧНИТЬ» сам не выдумывай.

## 3. Ветки и коммиты

- Основная ветка - `master` (владелец называет её «main»). **В неё напрямую не коммитить и не пушить.**
- Любая правка - в отдельной ветке `fix/<короткое-название-латиницей>`, созданной от свежей основной ветки.
- Эксперименты с дизайном, о которых прямо попросил владелец, - в ветках `experiment/<название>`.
  Они тоже получают предпросмотр и тоже не сливаются без его решения.
- Одна ветка - одна задача. Попутные улучшения не добавляй, предложи их отдельно.
- В основную ветку изменения попадают только через pull request, после того как владелец посмотрел
  предпросмотр и сказал «ок». Сам PR не сливай, пока тебя об этом не попросили.
- Тег `v1.0` не перемещать и не удалять.

## 4. Перед тем как показать результат

Обязательно, каждый раз:

1. `npm run build` - сборка без ошибок. `npx eslint src` - без ошибок и предупреждений.
2. Открой собранный сайт (`npm run serve`, http://localhost:3219, либо конфигурация `gasanov-static`
   из `.claude/launch.json`) и проверь страницу на **390 px** и на **1440 px**:
   изменённый блок, соседние блоки, отсутствие горизонтальной прокрутки, консоль без ошибок.
3. Убедись, что не изменилось ничего, кроме заказанного: `git diff master --stat`.
4. В отчёте скажи прямо, что проверено, а что нет.

`npm run dev` для финальной проверки не годится: стили в нём иногда обновляются с опозданием.

## 5. Технические заметки

- Сайт - статический экспорт (`output: "export"`), серверного кода нет.
- Скролл-эффекты живут в `src/components/LateBundle.tsx` и подгружаются после загрузочного экрана.
  Не импортируй `gsap` в компоненты, которые нужны для первой отрисовки, - это ухудшит скорость загрузки.
- Картинки кладутся в `assets/originals` и нарезаются командой `npm run images`. Напрямую в `public/images` не клади.
- Адрес в подпапке (GitHub Pages) задаётся переменной `NEXT_PUBLIC_BASE_PATH`. Любой путь к файлу из `public`
  строй через `BASE_PATH` из `src/lib/basePath.ts`, иначе на GitHub Pages он сломается.
- Требования к скорости: Lighthouse на мобильном - Performance не ниже 90, Accessibility не ниже 95.
  После заметных правок перемеряй.
